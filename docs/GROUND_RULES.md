# 🤝 Gyuniverse Ground Rules

Gyuniverse의 협업 규칙은 통제를 위한 규칙이 아니라, 팀의 작업 흐름과 의사결정이 명확하게 남도록 하기 위한 최소한의 약속입니다.

## Communication

- 빠른 질문과 논의는 Discord 등 실시간 채널에서 진행합니다.
- 해야 할 일과 진행 상태는 Jira에 기록합니다.
- 중요한 기술 선택, 범위 변경, 정책 결정은 Notion Decision Log에 남깁니다.
- 코드 변경과 리뷰 기록은 GitHub에 남깁니다.
- 문제가 오래 막히기 전에 팀에 공유합니다.

## Development

- 작업 시작 전 관련 Jira Issue를 확인합니다.
- Branch 이름에 Jira Issue Key를 포함합니다.
- 주요 Branch에 직접 Push하지 않는 것을 원칙으로 합니다.
- 변경 사항은 Pull Request를 통해 공유합니다.
- Pull Request는 최소 1명의 Review를 거칩니다.
- CI가 구성된 이후에는 필요한 검증이 통과한 뒤 Merge합니다.

## Documentation

- 회의록은 논의 과정과 액션 아이템을 기록합니다.
- Decision Log는 최종 결정과 판단 근거를 기록합니다.
- Trouble Shooting은 문제, 원인, 시도, 해결 결과를 기록합니다.
- AI/RAG 실험은 조건과 결과를 함께 기록하고 최종 선택 근거와 연결합니다.

## Team Principle

- 담당 영역이 달라도 핵심 사용자 흐름과 프로젝트 방향은 함께 이해합니다.
- 역할은 고정된 직무명보다 실제 기여와 산출물을 기준으로 설명합니다.
- 기능을 단순히 많이 만드는 것보다 합의된 흐름을 끝까지 완성하고 검증합니다.
- Sprint Review와 Retrospective에서 협업 방식 자체도 개선합니다.
