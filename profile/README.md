## 🤝 Team Rules

### 💬 우리는 이렇게 소통합니다

- 의견에는 이유와 근거를 함께 이야기합니다.
- 반대 의견을 제시할 때는 가능하면 대안도 함께 제시합니다.
- 막힌 문제를 혼자 오래 끌지 않고 팀에 공유합니다.
- 도움이 필요하면 부담 없이 요청하고, 도울 수 있을 때 적극적으로 돕습니다.
- 역할과 담당 영역을 존중하되 필요한 의견은 자유롭게 나눕니다.
- 의견 충돌을 개인의 문제로 만들지 않고 문제 자체를 기준으로 논의합니다.
- 결정된 내용과 중요한 변경사항은 관련 팀원에게 바로 공유합니다.

### ✅ 우리는 이것을 꼭 지킵니다

- 일정이나 계획에 변동이 생기면 최대한 미리 공유합니다.
- 맡은 작업의 진행 상태를 팀이 알 수 있게 유지합니다.
- 약속한 마감은 지키고, 어렵다면 마감 전에 공유합니다.
- 회의 전 필요한 질문과 논의할 내용을 준비합니다.
- 회의에서 결정된 내용과 후속 작업을 확인합니다.
- 팀 전체 일정에 영향을 주는 문제는 우선 공유합니다.

### 🧠 우리는 이렇게 결정합니다

- 중요한 선택에는 후보와 선택 이유를 남깁니다.
- 기술적 선택은 가능한 경우 실험이나 근거를 바탕으로 판단합니다.
- 의견이 다를 때는 근거를 비교하며 합의를 먼저 시도합니다.
- 합의가 어려운 경우 담당자 또는 PM의 판단을 우선하고, 필요하면 팀 투표를 활용합니다.
- 새로운 근거가 생기면 기존 결정도 다시 검토할 수 있습니다.
- 결정이 변경되더라도 기존 기록을 지우지 않고 변경 이유를 남깁니다.

### 💻 우리는 이렇게 개발합니다

- 개발 전 작업 내용을 팀과 공유하고 Jira에 반영합니다.
- Jira Work Item Key를 Branch와 Pull Request의 공통 연결고리로 사용합니다.
- 주요 변경사항은 Pull Request를 통해 공유하고 Review를 거칩니다.
- 중요한 문제와 해결 과정은 Trouble Shooting으로 남깁니다.
- 코드보다 팀 합의가 먼저 필요한 변경은 구현 전에 논의합니다.
- 프로젝트별 Branch, Commit, PR, CI 규칙은 해당 Repository의 Development Convention을 따릅니다.
