### Development Flow

`Jira Issue → Branch → Commit → Pull Request → CI/Review → Merge → Jira Done`

## 🤝 Ground Rules

- 작업 시작 전 관련 **Jira Issue**를 확인합니다.
- Branch 이름에 **Jira Issue Key**를 포함합니다.
- `main` / `develop` 등 주요 Branch에는 직접 Push하지 않는 것을 원칙으로 합니다.
- 변경 사항은 **Pull Request**를 통해 공유하고 최소 1명의 Review를 거칩니다.
- 중요한 기술 선택, 범위 변경, 의사결정은 **Notion Decision Log**에 근거와 함께 남깁니다.
- 빠른 대화는 Discord 등에서 진행하되, 최종 상태는 각 담당 도구에 기록합니다.
- 문제가 오래 막히기 전에 공유하고, 해결 과정은 필요 시 Trouble Shooting으로 남깁니다.
